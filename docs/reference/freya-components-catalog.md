## Elements vs Components

Freya has **two layers**:

- **Elements** (`rect`, `label`, `paragraph`, `text`, `image`, `svg`, `Stack`, `Rect`, `Label`, …) are the
  low-level layout/render primitives — analogous to HTML tags. They carry layout/style attributes directly
  (`width`, `height`, `direction`, `padding`, `background`, `corner_radius`, `border`, `shadow`,
  `main_align`, `cross_align`, `content`, `offset_x/y`, `layer`, `position`). You compose UI out of these.
- **Components** (this catalog) are higher-level, **themeable, stateful** widgets built *out of* elements —
  `Button`, `Input`, `Menu`, `Popup`, `Slider`, `Table`, etc. They follow a **builder/`#[component]` pattern**:
  `Component::new(...)` then chained `.method(...)` setters, ending implicitly when rendered.

**Rule of thumb:** reach for a **component** if one exists; drop to **elements** only for custom layout/containers
that no component covers. Most components expose a `.theme(...)` / `.theme_colors(...)` / `.theme_layout(...)`
method taking a `XThemePartial` so you can override just the fields you care about.

> The component builder structs implement shared extension traits (`LayoutExt`, `ChildrenExt`, `ContainerExt`,
> `AccessibilityExt`, `TextStyleExt`, `EventHandlersExt`, `KeyExt`) — so most components also accept the
> standard layout/key/a11y methods (`.width()`, `.height()`, `.key()`, `.a11y_*()`) even when not listed below.

## Crate Index

| Crate | One-line purpose |
|-------|------------------|
| `freya` | Umbrella crate — cross-platform, non-web GUI library powered by Skia; re-exports everything via `freya::prelude`. |

| `freya-code-editor` | Composable code-editor APIs (syntax-aware editing) for Freya. |
| `freya-router` | Router management for Freya apps (routes, `Link`, native router, animated router). |
| `freya-testing` | Headless testing APIs — render + drive components without a window. |
| `freya-engine` | Abstract graphics API layer (Skia abstraction). |
| `freya-winit` | Winit renderer + window/event-loop management for desktop. |
| `freya-i18n` | i18n/localization integration based on the Fluent Project. |
| `freya-icons` | Icon assets library (Lucide icons via the `lucide` feature). |

## Hooks

### `use_animation` / `use_animation_with_dependencies`
- **Source:** `crates/freya-animation/src/hook.rs`
```rust
pub fn use_animation<A: AnimatedValue>(run: impl 'static + FnMut(&mut AnimConfiguration) -> A) -> UseAnimation<A>;
pub fn use_animation_with_dependencies<A: AnimatedValue, D: 'static + Clone + PartialEq>(
    dependencies: &D, run: impl 'static + FnMut(&mut AnimConfiguration, &D) -> A,
) -> UseAnimation<A>;
```
- The closure returns an animated value (or tuple): **`AnimNum`** (numeric) / **`AnimColor`** (color).
  Each: `AnimNum::new(from, to).time(ms).ease(Ease).function(Function)`; read with `.value()`.
- Returned `UseAnimation<A>`: `.get()`, `.start()`, `.reverse()`, `.reset()`, `.finish()`, `.run(AnimDirection)`, `.is_running()`, `.has_run_yet()`.
- Config enums (set on `AnimConfiguration`):
  - **`OnCreation`**: `Nothing` (default) / `Run` / `Finish`
  - **`OnFinish`**: `Nothing` (default) / `Reverse { delay }` / `Restart { delay }`
  - **`OnChange`**: `Reset` (default) / `Finish` / `Rerun` / `Nothing`
  - **`Ease`**: `In` / `Out` (default) / `InOut`
  - **`Function`**: `Linear` (default) / `Quad` / `Cubic` / `Quart` / `Sine` / `Back` / `Bounce` / `Circ` / `Elastic` / `Expo`
